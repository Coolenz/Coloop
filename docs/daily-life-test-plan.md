# 生活场景实机验收测试集

共 **30 项：24 个生活任务 + 6 个恢复场景**。当前均为 `NOT_RUN`，这是新设计，不把此前的实测自动算入本套结果。结构化定义见 [daily-life-taskset.json](../tests/daily-life-taskset.json)。

执行时将对应条目的 `prompt` 发给 Coloop，让模型自行选择脚本、浏览器、软件 API 或鼠标键盘。每次尝试使用独立目录；验收驱动只负责准备、故障注入与读证据，不替模型完成任务。此 JSON 为验收规格，不接入旧的 `action-taskset` 动作驱动。

## 每项的执行准备与提示词

### L01 记事本备忘

- 准备：空任务目录；已安装记事本。
- 发给 Coloop：在任务目录创建 weekend.txt，写三行：周六买菜、周日洗衣、周日晚整理下周计划；用记事本打开。
- 验收：读回恰好三行且顺序一致；实际记事本窗口打开该文件。
- 证据：weekend.txt；实际窗口标题及编辑区文本。
- 恢复检查：打开记事本后切换至工作台一次，再继续核验。

### L02 修改购物清单

- 准备：shopping.txt：鸡蛋10个、番茄3个、大米1袋，各占一行。
- 发给 Coloop：打开测试购物清单，将鸡蛋数量由10改为12，新增牛奶2盒，其余内容保持一致并保存。
- 验收：四行分别为鸡蛋12个、番茄3个、大米1袋、牛奶2盒；非目标行逐字一致。
- 证据：修改前后文件差异；保存后独立读回。
- 恢复检查：读取后、保存前切换到另一测试窗口；须重新确认目标。

### L03 另存与编码

- 准备：diary.txt：今天散步🌳\n心情不错；原文件记录SHA-256。
- 发给 Coloop：将测试日记另存为“周末日记-副本.txt”，保留中文、emoji和换行，不改变原文件。
- 验收：副本Unicode内容完全一致；原文件摘要不变；副本可在记事本打开。
- 证据：两个文件摘要、Unicode字符与窗口读回。
- 恢复检查：第一次观察故意过期，重新读取后完成。

### L04 计算器算分摊

- 准备：计算器可用；新计算状态。
- 发给 Coloop：用Windows计算器实际计算晚餐286元加停车24元，5人平摊，报告每人金额。
- 验收：计算器实际显示62；回答为每人62元。
- 证据：实际显示值或计算器可访问性读回；任务答案。
- 恢复检查：输入前短暂切换窗口，不能把数字发到其它应用。

### L05 家庭资料分类

- 准备：仅操作独立fixture/inbox，含2个命名为发票的PDF、2张JPG、2个TXT；固定摘要清单。
- 发给 Coloop：将测试资料按发票、照片、其他分到子目录，生成整理清单。
- 验收：6个文件分类正确；无遗漏或重复；逐文件摘要不变；清单记录原路径和新路径。
- 证据：目录树、清单与整理前后摘要。
- 恢复检查：移动一部分后中断观察，继续时根据真实目录补齐，不能重复移动。

### L06 旅行照片重命名

- 准备：4张测试照片有不同EXIF拍摄时间；目录另有已存在的同名文件，禁止覆盖。
- 发给 Coloop：把测试照片按拍摄顺序重命名为“杭州旅行-001.jpg”起的连续文件名，输出可恢复映射。
- 验收：按EXIF而非文件系统时间排序；4张均保留；冲突另选不覆盖名称；映射能定位每张原图。
- 证据：EXIF时间、重命名映射和文件摘要。
- 恢复检查：重命名第二张后观察失效，凭映射与磁盘状态继续。

### L07 查找重复下载

- 准备：6个测试文件形成2组内容重复；其中含同名不同内容与异名同内容。
- 发给 Coloop：扫描测试下载目录，找出内容重复的文件，生成重复报告，暂不删除。
- 验收：按内容摘要得到准确2组；同名不同内容不误报；所有源文件仍存在。
- 证据：重复报告及原目录摘要快照。
- 恢复检查：扫描中暂时无法截图，改用脚本继续。

### L08 备份生活资料

- 准备：测试目录含中文文件名、空目录、2层子目录；排除输出ZIP自身。
- 发给 Coloop：把测试票据和清单打包为生活资料.zip，核验压缩包可解压且内容完整。
- 验收：解压后相对路径及所有文件摘要一致；空目录保留；ZIP不递归包含自身。
- 证据：ZIP、清单与独立解压目录对比。
- 恢复检查：核验首次失败时先检查ZIP，不能直接宣称备份成功。

### L09 家庭月账汇总

- 准备：ledger.csv有8笔：餐饮35.5、餐饮24.5、交通6、日用品18、餐饮45、交通12、娱乐60、日用品9，按预置日期分布。
- 发给 Coloop：汇总测试家庭账本，输出总支出、分类支出和每日支出CSV。
- 验收：总支出210元；餐饮105、交通18、日用品27、娱乐60；每日合计与输入一致。
- 证据：汇总CSV、原始8笔账与独立精确金额计算。
- 恢复检查：首次脚本格式错误后应纠正重跑；不能漏算或重复记账。

### L10 账单去重导入

- 准备：A/B各4条，共享2个交易ID，其中1个ID金额不同；另有两笔同金额不同ID。
- 发给 Coloop：合并两份测试账单，按交易编号去重，保留所有不同交易并输出冲突报告。
- 验收：并集6个ID；金额冲突单列且不擅自选值；同金额不同ID均保留；未冲突金额可独立求和。
- 证据：合并结果、冲突清单、输入文件摘要。
- 恢复检查：中途重试不得生成重复交易。

### L11 共享出游结算

- 准备：三人甲乙丙；甲支付300元、乙支付90元、丙支付60元，均为共同支出。
- 发给 Coloop：根据测试出游账本按三人均摊，生成最少转账次数的结算建议，不实际转账。
- 验收：每人应承担150元；乙向甲60元、丙向甲90元；总净额为零。
- 证据：结算JSON、两条建议及独立平衡检查。
- 恢复检查：任务重规划后金额和参与人不丢失。

### L12 七天购物预算

- 准备：提供固定菜单与单价CSV；番茄200克与0.3千克需要合并，鸡蛋以个计，缺价格的牛奶明确标记。
- 发给 Coloop：按测试一周菜单合并同名食材，生成数量清单和预计采购总价。
- 验收：番茄统一为500克；不同单位不能混加；牛奶价格未知；仅已知项目有小计，总价明确为已知部分。
- 证据：规范化食材CSV、单位换算和逐项小计。
- 恢复检查：核验发现单位错时重新计算，不直接结束。

### L13 网页预约草稿

- 准备：本机fixture预约页；日期、人数、姓名、备注控件；无外部提交。
- 发给 Coloop：在本地预约测试页选择2026-11-14下午14:30、2人、姓名测试用户，提交到本地模拟确认页。
- 验收：确认页字段与输入全部一致；提交事件计数恰好1。
- 证据：提交前后DOM快照、模拟事件日志与截图。
- 恢复检查：点击提交后丢失回执；先读确认记录，不能重复提交。

### L14 网页买菜清单

- 准备：fixture商品鸡蛋12元/份、牛奶8元/份；初始空购物车；不连接真实支付。
- 发给 Coloop：在本地测试买菜页搜索鸡蛋，加入2份鸡蛋和1份牛奶，停在购物车。
- 验收：购物车两种商品，数量2和1，总额32元；无支付事件。
- 证据：购物车DOM、独立本地购物车记录、事件日志。
- 恢复检查：加购回执延迟，先读购物车后决定是否补操作。

### L15 快递状态整理

- 准备：fixture单号TEST001已签收、TEST002运输中、TEST003未找到；查询结果异步显示。
- 发给 Coloop：在本地快递查询页逐一查询三条测试单号，保存状态和更新时间。
- 验收：三条分别匹配；未找到不编造进度；每条对应正确单号与时间。
- 证据：查询结果JSON、每条单号与页面证据。
- 恢复检查：第二条加载延迟及切换窗口，须等待对应单号结果。

### L16 公开菜谱摘录

- 准备：执行前指定一个无需登录、包含完整菜谱的URL，并留存页面基线；不使用未指定的私人页面。
- 发给 Coloop：从指定公开菜谱页面提取名称、食材和做法，整理为本地菜谱卡。
- 验收：关键食材数量、步骤及来源与页面一致；没有的份量填未知；保存URL和采集时间。
- 证据：菜谱卡、原页面文本及截图；独立逐字段核对。
- 恢复检查：页面延迟或元素变化时重新读取DOM，不凭旧坐标继续。

### L17 城市天气整理

- 准备：执行时可访问的明确天气来源；使用当次真实日期和时区，不固定历史预报。
- 发给 Coloop：查询杭州接下来3天的天气，整理日期、天气、最高最低温和来源。
- 验收：与采集页面的3个自然日对应；温度单位一致；缺失字段明确标注，不用常识补值。
- 证据：带来源URL、采集时间及日期的JSON；页面快照。
- 恢复检查：首个来源超时后重试或换来源，并记录来源变化。

### L18 展馆出行信息

- 准备：指定真实官网URL；执行前确认页面公开可读；只整理，不实际预约。
- 发给 Coloop：从指定博物馆官网整理地址、开放时间、闭馆日和预约入口，保存出行备忘。
- 验收：四字段均有官方来源；预约要求和闭馆日保留限定条件；缺失项标未知。
- 证据：出行备忘与官方原文片段及URL。
- 恢复检查：新标签页打开后绑定正确URL，不能在原页面旧目标上点击。

### L19 通勤路线对比

- 准备：执行前给出公开测试地标A/B；不使用家庭地址；明确查询时间和地图站点。

- 验收：两方案方向与起终点正确；保留页面单位、换乘及查询时间；不编造缺失路线。
- 证据：地图当前URL、路线文字、截图与结构化结果。
- 恢复检查：切换公交/步行后重新读页面；不得复用上一方案数值。

### L20 视频排行榜收藏单

- 发给 Coloop：读取Bilibili官方综合排行榜前10个名次，保存标题、UP主、播放数和链接到本地观看清单。
- 验收：官方来源；名次1至10；链接非空且唯一；播放数与页面对应；采集时间完整；不实际收藏账号。
- 证据：JSON、截图、原始排名属性及独立读回。
- 恢复检查：懒加载、重复排名和长输出均触发纠正；完成状态与实际产物一致。

### L21 视频搜索去重

- 准备：搜索页面公开可访问；按当次页面默认顺序；不登录、不播放受限内容。
- 发给 Coloop：在Bilibili搜索“家常菜教程”，整理前8个实际视频的标题、UP主和链接，广告另列。
- 验收：8条去重视频；非视频卡片不混入；广告标识保留；若不足8条据实说明。
- 证据：搜索URL、排序方式、采集时间、卡片证据与JSON。
- 恢复检查：结果异步刷新后重新确认关键词与排序。

### L22 浏览器到记事本

- 准备：提供一篇可公开访问的文章URL；任务目录为空；只摘要该篇文章。
- 发给 Coloop：从指定公开文章提取标题和3个要点，保存阅读摘记.txt并用记事本打开。
- 验收：标题准确、3个要点有原文支持；包含来源URL；文件内容与实际记事本一致。
- 证据：原文快照、摘记文件、编辑区实际读回。
- 恢复检查：浏览器到记事本切换不能终止任务或把文本写到浏览器搜索框。

### L23 周末行程草案

- 准备：fixture活动4项，含固定时段、2个同地点活动及1个时间冲突；另附步行时间矩阵。
- 发给 Coloop：根据测试活动表生成周末时间表，将地点相同的活动合并成一段出行，保存行程和待办。
- 验收：不重排固定时段；明确指出冲突；合并同地点出行且预留给定路程；不把冲突行程当可执行安排。
- 证据：行程文件、冲突清单与时间区间核对。
- 恢复检查：计划修订时保留原始固定约束，不因历史上下文裁剪而丢失。
