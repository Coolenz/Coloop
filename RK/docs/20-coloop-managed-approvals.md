## 使用入口

启动 Coloop，导入 RK 连接配置并连接设备。在「Agent 协调」复制显示的受控启动命令。默认板端入口为：

```bash
bash "$HOME/rk-opencode/scripts/coloop-managed.sh"
```

工作目录是选定应用目录的 `workspace/`。Agent 使用 `coloop_read`，参数为该目录内的相对 POSIX 路径。连接会备份更新本任务插件、核心模块、活动租约助手、启动器及固定配置，并写入 `0700/0600` 私有连接文件；不会安装模型或替换 Runtime。断开再连接后应重新启动来源会话，旧签名授权不会转移到新连接。

旧 `coloop-opencode.sh` 保留普通 OpenCode/MemoryPlugin 行为，旧内置 `read` 的 allow 仍不会自动执行。受控入口另建私有 HOME/XDG，固定本地 RK provider 与两个已核对插件，禁用项目配置、自动共享/更新、自动压缩和 MCP；不加载长期记忆插件。启动不会清理普通会话或已有记忆。

## 审批如何约束实际数据

- 工具从 `/` 开始逐级通过目录 fd 和 `O_NOFOLLOW` 打开路径，拒绝符号链接、硬链接和敏感路径；最多扫描 64KiB。文本须为有效 UTF-8，无二进制/控制字符。检测包括凭据、部分个人信息、JSON 转义/嵌套、Unicode 全角和不可见字符，扫描副本不改变原文件。
- 扫描后最多返回 4096 UTF-8 字节。完整快照及返回片段分别计算 SHA256，明确标记截断；审批期间文件被删除、替换或改为链接，也不会重新打开并返回新内容。
- 来源证据绑定 source、instance、session、task、message、PID、路径、字节数和双摘要。主机通过固定指纹 SSH 核对配置、插件源码摘要、来源进程可执行文件与关键环境，再把精简扫描结果交给 RK。受控审批不发送文件正文或会话历史给审批模型。
- 只有实际 RK allow 才能生成 Ed25519 签名许可。私钥只在 Coloop 主进程内存，来源仅获公钥。许可绑定请求摘要、冻结快照、会话/任务、有效期及随机 nonce；插件必须验签并复查原 pending 后才发送一次 `once`。
- 工具还必须消费进程内一次性许可，并在实际返回前重查任务、配置、取消与 monotonic 截止时间。手动点允许、模型自称成功、普通 `allow` JSON、过期/断连或旧会话回复都不能替代该许可。不会发送 `always`。
- 受控读取最终无法确认安全时自动拒绝，避免无人值守时无限等待。已经发起但结果不明的回写不会重试；已经失效的上下文不能再获得另一条“补救”回写。

这是一条软件信任边界：本机当前 Windows 用户、板端应用用户及操作系统属于可信运行环境。它不等价于 Violoop 独立 MCU/物理按钮隔离，也不能抵御这些账户或内核已被攻破的情形。凭据检测为保守规则，不是任意秘密识别的完备证明。当前可自动放行的是该受控读取和既有安全选择，任意 Shell、写入、联网、跨应用动作及 Codex 桌面原生审批仍未接入。

## 上下文与记忆

沿用 Hook 的来源/实例/会话/任务隔离、限额、过期与压缩失效机制。普通安全选择最多使用 192 UTF-8 字节状态投影；受控文件审批仅使用经过认证的扫描元数据。原始正文不会进入 Coloop 普通任务历史，审批审计只记录摘要、原因码和耗时。

受控会话不召回、提取或写入 Mem0；仅登记自己的前台活动并等待已经开始的一次维护排空，结束后释放。来源突然终止时，私有租约目录中的 PID/来源标识支持只清理已死亡进程的自有记录。现有普通聊天记忆仍按原规则运行，不能将受控入口的限制推广成所有 OpenCode 会话均不保存文本。

原生 OpenCode 会话数据库仍可能保存用户消息和已批准的文件结果。本次合成验收的输入、随机串和原始输出另行留档；不是物理安全擦除。真实敏感材料不应用作这些测试的 fixture。
