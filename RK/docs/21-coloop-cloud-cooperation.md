工作台默认由 RK 判断简单／复杂。简单任务本地回答；复杂任务先由本机规则和 RK 脱敏摘要，再由 RK 复核，主机冻结检查后仅将必要 `{question, facts}` 发给云端。云端 Agent 返回简短结论／步骤／不确定项 JSON，主机校验后交 RK 结合本地资料核查，最后在本机恢复必要的非凭据实体。凭据移除且不回填，云端不能获得映射或额外执行许可。

云端实体引用范围绑定本次实际出境摘要。最终 RK 使用仅本地的短实体 ID 与映射，输出严格的「实体 ID 列表＋通用分析正文」；主机按 RK 选择的合法已有 ID 精确呈现身份／业务原值，凭据不能恢复。未知／重复 ID、非法正文或格式错误拒绝，不模糊纠错或修补模型原文。模型仍可能选错实体、遗漏条件或改变语义，因此隐私闸门和最终任务质量分别计分。

敏感边界采用用户确认的严格策略：凭据、身份／联系方式、内部路径／地址、业务私密内容留在本地；参考 Violoop 的本地优先思路，但其公开政策没有逐字段规范，也不代表本项目具有其硬件隔离能力。

目前只处理本次问题和附加上下文，不拼入历史或 Mem0。协作的全部 RK 请求使用 `metadata-only` 回执和禁缓存、禁工具路径；只登记自有前台活动。所有控制 JSON、云端完成原因和占位符都必须验证，失败不回退原文上云。旧 `target: cloud` 请求同样经此流程。原有 RK-only 任务和本地明文历史的行为另按既有说明判断。

语义隐私判断依赖 RK，主机仅对已知形式和已登记片段做确定性复核；不是完整 DLP 证明。协议测试、真实 NPU 输出质量、实际云账户调用和最终业务成功分别验收。新的原始证据使用 `logs/coloop-cooperative-*`，不引用旧审批题的通过率或延迟证明本次协作有效。
