# 在鲁班猫 4 上部署 Qwen3.5-9B

2026-10-29 上下文更新：日常启动默认 **16384 token（16K）**，允许 512～16384；上限依据当前固定 `.rkllm` 文件报告的 `max_context_limit: 16384`。原先的默认 2048、上限 4096 是本项目自设的保守限制。来源、验证结果与评测复现边界见 [上下文配置说明](16-qwen35-context.md)。

## 方案和当前状态

目标是本地文字问答和单张图片问答，不包含桌面控制或完整 VioLoop 功能。

使用 Qengineering 社区转换的 RK3588 模型，跳过电脑端完整原始模型转换。
原始模型来自 [Qwen/Qwen3.5-9B](https://huggingface.co/Qwen/Qwen3.5-9B)。
转换文件不是阿里或瑞芯微官方发布的权重。

2026-10-28：两个模型均已下载、上传，并在电脑及板端通过 SHA256 校验；
应用已在实际 LubanCat-4 V1（16GB/128GB）上编译并完成 NPU 推理。

**当前为实验部署：看图样例通过人工核对，纯文本质量验收未通过。**
月球样例图片中，模型正确描述了宇航员、月球表面、背景地球和绿色啤酒瓶。
纯文本算术题却出现无关文字、数字被替换、前后矛盾等现象。退出码0只说明程序执行完毕，
不能视为回答正确。不应把当前社区量化文件当成已验证可用的通用助手。

1.3.0与1.3.1运行库、内置/自定义对话模板、缓存初始化、短/长文本及16K上下文对比，
均未消除文本异常；根因尚未定位。输入补齐没有通过验证，已从最终应用移除。
原始输出和监测记录保存在 `logs/qwen35-*-smoke.txt` / `logs/qwen35-*-status.json`。

2026-10-28 追加复测：固定2048上下文、64个输出token、关闭思考，每题重新启动模型进程，

## 固定来源

- 模型：[Qengineering/Qwen3.5-9B-rk3588](https://huggingface.co/Qengineering/Qwen3.5-9B-rk3588)。
- 模型仓库版本：`8e14580be5ac58feadd2f463efd4200963ec7b9e`。
- 配套源代码：[Qengineering/Qwen3.5-9B-NPU](https://github.com/Qengineering/Qwen3.5-9B-NPU)。
- 源代码版本：`304aaaa1c1b6c70bcea2c3df37572e828994fe0a`。
- 应用内 RKLLM Runtime/Header：官方 1.3.0，与社区模型的转换版本匹配；从瑞芯微官方源获取并锁定 SHA256。
- 此应用使用自己的运行库，不替换现有 DeepSeek / 转换工具的1.3.1环境。
- RKNN Runtime：复制板上现有 `/usr/lib/librknnrt.so` 到本应用 `lib/`。

## 日常启动

在 Windows 双击：

- **运行Qwen3.5-9B.cmd**：实验性文字问答，启动时提示质量验收未通过。
- **看图Qwen3.5-9B.cmd**：对示例月球图片提问。

使用现有的开发板 SSH 密码登录。默认上下文为 16384、最多输出 128 token，关闭思考模式。
输入 `exit` 退出；`clear` 清空历史。看图模式会自动给问题补充 `<image>` 标记。

PowerShell 参数入口：

```powershell
powershell -ExecutionPolicy Bypass -File D:\RK\scripts\qwen35.ps1 -MaxNewTokens 256 -ContextLength 16384
powershell -ExecutionPolicy Bypass -File D:\RK\scripts\qwen35.ps1 -SampleImage
powershell -ExecutionPolicy Bypass -File D:\RK\scripts\qwen35.ps1 -BoardImage /home/cat/example.jpg
```

登录板子后：

```bash
cd ~/rk-edge-ai/qwen35
bash run.sh
bash run.sh --image samples/moon.jpg
bash run.sh --image /home/cat/example.jpg --tokens 128 --context 16384
```

上传自己的图片（在 Windows 执行，替换图片路径）：

```powershell
scp -F D:\RK\config\ssh_config C:\path\example.jpg lubancat4-usb:/home/cat/example.jpg
```

## 从头准备和部署

本项目 PowerShell 中：

```powershell
cd D:\RK
.\.venv\Scripts\python.exe tools\prepare_qwen35.py
.\.venv\Scripts\python.exe tools\deploy_qwen35.py
.\.venv\Scripts\python.exe tools\smoke_qwen35.py
.\.venv\Scripts\python.exe tools\smoke_qwen35.py --image
```

准备脚本支持分片续传并检查 SHA256。电脑需同时容纳下载分片和合并文件，建议至少25GB空闲。
官方站链路较慢时可给准备命令加 `--mirror`，通过直连 hf-mirror.com 传输，仍使用官方
Hugging Face 固定版本的字节数和 SHA256 验收；不会修改系统代理设置。
部署脚本上传后在板端再次检查 SHA256，续传使用 `.partial` 文件，不把未完成文件当成模型。
脚本会提示开发板密码；密码不写入文件。可通过已有 `RK_BOARD_PASSWORD` 环境变量传入。

可分阶段部署：

```powershell
.\.venv\Scripts\python.exe tools\deploy_qwen35.py --stage dependencies
.\.venv\Scripts\python.exe tools\deploy_qwen35.py --stage runtime
.\.venv\Scripts\python.exe tools\deploy_qwen35.py --stage models
```

依赖为 `libopencv-core-dev`、`libopencv-imgproc-dev`、`libopencv-imgcodecs-dev` 和验收用的 `time`。
安装通过本次 SSH 会话的回环代理访问电脑网络，不写入系统代理配置。
安装依赖前，脚本会检查板端时钟；与电脑相差超过2分钟时，以电脑时间校准板卡，
避免软件源签名时间检查失败。本次曾校准与电脑相差约8小时47分的板卡时钟。

## 与上游示例的差异

- 初版曾把上游默认 16K 上下文改为 2048、可选上限 4096；2026-10-29 日常入口恢复默认 16K，上限按固定模型文件的 16K 限制校验。生成上限仍默认 128。
- 允许不加载视觉编码器的纯文本模式。
- 修复终端 EOF、UTF-8 校验、输出流式刷新。
- 修复回调同步和错误传播，RKNN 按实际输出数量释放结果。
- 移除上游硬编码的对话模板，使用模型内置模板，保留 `enable_thinking` 的正常处理。
- 运行库置于应用 `lib/`，使用匹配的官方头文件重新编译。
- 在应用入口使用文件锁避免同一应用多开；其他大模型应用仍需自行退出后再运行。

所有补丁由 `tools/build_qwen35_bundle.py` 重建，生成的文件与摘要在
`deployment/qwen35/source-manifest.json`。不按上游 README 的复制残留命令全局替换运行库。

## 验证和边界

本板看图实测（单张448×448编码、2048上下文、最多128输出token）：

- 初始化约22.62秒；包含预填充的问答约31.59秒；完整进程约59秒。
- 实际生成72 token，约2.94 token/秒。
- `/usr/bin/time` 最大RSS为9,592,948 KiB，约9.15 GiB；未使用交换。
- 这些数据来自一次样例，加载时间受文件缓存影响，不是冷启动或持续性能保证。

测试脚本单次运行最长600秒，每5秒采集可用内存和温度，温度达到80℃停止本次测试。
输出保存在 `logs/qwen35-text-smoke.txt` / `logs/qwen35-image-smoke.txt` 及对应状态JSON。
这些是短时验收，不代表长时间稳定性或通用推理能力测试。

日常入口现按固定模型文件使用 16K 上下文配置；下列历史性能记录仍是 2048 设置，不能直接沿用为 16K 性能。新配置验证见 [上下文配置说明](16-qwen35-context.md)。多帧视频未验证。
图片会缩放、补边到视觉模型固定尺寸，小字、密集表格和精细坐标任务需要另做准确率验证。
