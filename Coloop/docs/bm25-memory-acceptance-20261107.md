# BM25 混合记忆检索验收

2026-11-07，已部署至 RK 正式 Mem0 服务。源码在 `D:/RK/rk-opencode` 子仓库，提交为 `20ecdde` 与 `51a67a1`。Coloop 通过现有 MemoryClient 接口使用新检索，运行中的桌面安装版可直接生效。

## 实现

- SQLite FTS5 提供 BM25，BGE 与 Qdrant 提供稠密向量候选，RRF 采用 k=60 融合两份排名。
- 中文采用重叠双字切分，Latin 标识保留完整形式及标点分段，NFKC 与大小写归一化。FTS 输入编码后绑定参数，查询中的操作符作为文本处理。
- 在当前项目、有效期、最新版本和标签过滤后的有效事实集合上即时建立内存 FTS 索引，覆盖正文、逻辑键、标签和目录摘要。已有事实立即可查，修改及删除即时生效。
- catalog、search、recall，以及记忆管理 browse 的语义候选路径使用混合排名。browse 保留字面命中的优先处理和既有 API mode 值，普通候选依照融合排名排列。
- 私密引用继续由受保护目录处理。目录接口继续只返回摘要和标识，正文由 get_many 按 ID 读取。search 中既有 score 字段继续表示稠密分数，关键词独有结果的 score 为 null。

## 验证与部署

- 记忆相关回归 37 项、私密记忆回归 9 项通过，Ruff 检查通过。相关日志为 `.qa/bm25-tests.log` 和 `.qa/bm25-private-tests.log`。
- RK 上真实 Mem0、BGE、Qdrant 与鉴权 HTTP 验证通过，覆盖错误码、文件名、中文主题、同义表达、管理查询、来源范围、更新/删除及重开持久库。
- 四个合成查询的目标均排第一。原稠密检索在这四个样例也均排第一，因此本批结果仅说明检索有效。额外单元回归确认 BM25 能补回稠密候选外的精确词记录，并保持融合顺序。
- 合成样例查询耗时约 15–26 ms，使用六条事实及已加载模型。大规模库性能和真实任务召回率需后续测量。
- 正式服务报告 `bm25_rrf_v1` 能力，生产 catalog 读取通过。部署前后事实、版本、标签、摘要目录和任务队列整体摘要一致，共 91 条 entries，包含历史及摘要记录。
- 本次测试模型推理调用为 0。远程临时源码和隔离测试库已清理，保留小型报告及部署源码哈希。
