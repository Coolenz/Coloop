# Violoop 手机任务

2026-10-31。手机到 RK 桌面任务的第一阶段接入。用户在已配电脑中点击「给 Violoop 发任务」，发送自然语言目标。电脑端通过已有加密网关接收，RK 本地模型解析任务；可执行时启动独立 DesktopTaskService，由板端运行时组织观察、规划、HID 和结果回读。OpenCode 会话消息入口继续独立存在。

后续真实 RK 联调已完成：既有 Android 0.3.0、真实公网连接、真实 RK 模型/自动本地路线、USB HID 和独立结果核对通过。当前 `start-violoop.cmd` 优先启动 `release/violoop-rk-0.12.0/win-unpacked/Coloop.exe`；无需重新安装另一个 APK。固定证据、修复和限制见 [实机联调](violoop-rk-live.md)。下文首轮模拟验收记录保留，不改写成实机证据。

## 当前能用的范围

- 向 Violoop 发送新任务，查看接收、解析、执行、验证、停止和失败状态。
- 对缺少必要信息或超出当前能力的任务返回说明；可选择原任务补充信息。
- 已打开、标题唯一的单窗口，使用已有 UIA 输入框和按钮；每字段 1～64 个可打印 ASCII 字符。
- 自动规划模式使用桌面专用的 RK 路由策略，本地已验证的小型输入/确认任务优先本地处理；其他规划需求进入原有隐私协作通道。路由失败不会绕过隐私检查。
- 手机停止同时撤销任务解析与本次桌面执行，停止未确认时继续显示未确认状态。

例如在已打开的隔离测试窗口中发送：“在 Lab 窗口读取 Code 的数字，填入 Input，再点击 Apply。完成后出现 Applied:。”也可在「补充窗口与完成条件」中填写完整标题与完成文字。当前仍需让目标窗口保持前台；已有初始化阶段留出约 4 秒切换时间。

完成文字必须由用户明确提供，主机校验其来自本次任务消息或显式字段，再由 RK 运行时检查动作前不存在、动作后出现。该条件是文字观察核验，不等于通用业务语义验证。日志中的键鼠发送成功不作为任务完成证据。

## 使用

1. 退出托盘中的旧 Coloop，再用根目录 `start-violoop.cmd` 启动本专题配套程序。主目录 `start.cmd` 与其他专题启动器保持各自选择。
2. 在电脑连接 RK，确认本地模型、隐私服务和已有 USB HID 可用。运行时继续使用已配置的 Windows 观察环境。
3. 在「Agent 协调 → 安卓手机连接」开启已配置的自有服务器连接或临时隧道，扫码配对 Android 0.3.0。
4. 手机选中电脑，进入「给 Violoop 发任务」。提交按钮即授权本次目标范围内的电脑操作；执行中可随时停止。

产物位置为 `release/android/Coloop-Android-0.3.0-debug.apk` 和 `release/violoop-companion-0.12.0/win-unpacked/Coloop.exe`。这是独立开发构建，不是自动升级已安装版。APK 使用本项目既有调试签名，可覆盖同签名旧版。

## 任务与恢复

每条消息带客户端 UUID，接收前把消息摘要、来源设备和回执保存到 Windows DPAPI 加密的任务账本；再进入异步 RK 解析。网络超时后仅从快照核对该 UUID，不自动重发。相同 UUID 与内容重复到达只返回原回执；内容冲突或来自其他设备则拒绝。

电脑重启后，未结束任务标为中断并提示核查，不重新启动执行器。账本保留已接收 UUID，最多 1000 条，满后拒绝新增，不通过淘汰旧编号重新放行延迟请求。快照最多返回最近 20 项任务。账本损坏或无法加密保存时拒绝新任务，保留原文件。

账号密码管理、模型任务、会话控制和设置变更继续与 Violoop 任务互斥。顶部控制提示仍由实际桌面执行状态驱动，解析消息不构成正在输入。仅恢复控制不会继续旧任务。

## 验收与下一步

应用单元测试覆盖接收去重、旧 UUID、同内容重试、跨设备冲突、重启不重放、解析期间停止、迟到结果、停止未确认、无效目标及模型编造完成条件。Python 测试覆盖自动规划模式沿用原观察、动作组和结果校验边界。

本轮通过 529 项 Vitest、11 项 Android JVM、16 项 Python 执行器测试；真实 Android Emulator 的 6 项流程检查及最终 APK 的 3 项显示/离线检查通过。配套打包程序通过 4 项接入检查，原公网加密通道回归 7 项通过，原桌面控制提示回归 16 项通过。证据位于 `.qa/violoop-android-r4/verification.json`、`.qa/violoop-android-r4/final-apk-visual.json`、`.qa/violoop-companion-1793379281808/verification.json` 和 `.qa/mobile-1793379284359/results.json`；汇总与 SHA256 见 `release/android/violoop-0.3.0-verification.json`。前几轮测试自动化对短暂状态和列表滚动处理不足的失败保留在 `.qa/violoop-android/`、`-r2/`、`-r3/`。

运行时的 `planningCalls` 统计执行器请求规划的次数，不包含手机任务解析、路由判断和隐私检查的各次模型调用，不能当作总模型调用数或本轮速度改善证据。

`tests/violoop-android-host.ts` 是明确的测试后端，使用真实远程网关和任务接入服务，模拟 RK 推理及 HID。`tests/violoop-android-e2e.mjs` 在实际 Android Emulator 中验证加密配对、任务状态、手机进程恢复、停止、补充信息和深色/放大字体。测试后端仅使用本地模拟器地址及测试目录，不进入发行物。模拟结果不得记作真实 RK、云端模型或鼠标操作通过。

首轮只检查了 `COLOOP_TEST_BOARD_PASSWORD` 环境变量，未读取 RK 工程中已授权的连接资料，因此当时没有完成真实 RK/HID 验收。后续用户要求联调后，沿工程连接约定完成了独立的 [真实联调](violoop-rk-live.md)；凭据仅用于进程环境和连接，没有写入此文档或报告。
