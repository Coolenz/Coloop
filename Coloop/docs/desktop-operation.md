## 同页任务如何执行

按照用户最新要求，读取数字、填入输入框、点击确认等能在同一页面完成的任务，由模型一次返回动作组，RK 连续执行，整组结束后再统一观察和检查结果。

```text
初始窗口观察与 OCR
  → 压缩、去除 UIA/OCR 重复文字
  → 一次规划，返回最多 8 个同页动作
  → RK 预检整组并一次消费观察
  → 连续执行：填充字段 → 点击确认
  → 最终观察与 OCR → 检查完成文字
```

组内不调用模型，不做完整 OCR，也不逐动作记录业务进度。只保留快速 UIA 校验：窗口和显示坐标未变、目标仍是原控件、没有遮挡、输入焦点正确；每个动作的序号只消费一次。发生跳页、失焦、目标变化或停止时中断，不继续盲发剩余动作。

`fill` 是明确的字段替换动作：定位 Edit、通过 HID 聚焦，确认焦点后发送 Ctrl+A 与文本；不是追加一遍相同文字。`click` 和 `hotkey` 同样绑定初始观察里的 UIA 控件。OCR 识别文字保留为读取资料，不把纯文字框冒充可连续操作的按钮。

一次规划只携带控件编号、名称、类型、必要值与焦点，以及去重后的额外 OCR 文字。坐标由本机校验器掌握，不发给模型猜测。只有整组结束后的结果需要新决策时，才进入下一轮规划；默认最多 8 轮。

## 使用方法

1. 启动包含本功能的开发构建；先退出托盘中的其他 Coloop 实例。普通 `start.cmd` 仍保留其他功能的既有发行物选择。
2. 在设备管理导入 RK 配置、连接，并确认模型和隐私服务就绪。RK 需已有复合 USB 键盘、鼠标；当前设备已具备，不重刷系统或替换模型。
3. 打开「电脑操作」，刷新并选择完整且唯一的窗口标题，填写目标和完成时应出现的具体文字，选择规划模式，勾选本次输入授权。
4. 开始后切到目标窗口并保持前台；初始化后预留约 4 秒切换时间。首版限定单显示器，输入限每个字段 1～64 个 US 布局可打印 ASCII 字符。
5. 可通过页面按钮、独立顶部提示的 Stop 或托盘停止全部控制。只有收到 RK 撤销确认才显示已停止；断连而没有确认时保留未确认状态。

完成条件目前是去除空白后的文字包含匹配。应选择足以区分本次正确结果的文字；它不等于任意业务语义验证。若该文字在任务开始时已经存在，会拒绝用它证明新任务完成。测试台另用独立记录核对实际数字和提交次数。

## 分工与实现

| 模块                                      | 当前实现                                                          |
| ----------------------------------------- | ----------------------------------------------------------------- |
| `src/shared/desktop.ts`                   | 任务授权、有限动作组、固定 schema、状态与聚合指标                 |
| `src/main/services/desktop-tasks.ts`      | 应用接入、互斥、规划适配、控制提示与停止确认                      |
| `src/main/infrastructure/desktop-pipe.ts` | 有大小限制的私有 JSON Lines 子进程/SSH 通道，无新 TCP 服务        |
| `resources/desktop-runtime.py`            | 在 RK 上持有任务循环、组内顺序和停止状态；按整任务持有共享 HID 锁 |
| `resources/desktop-observer.py`           | 电脑端观察、一次性批次许可和无 OCR 的即时 UIA 校验                |
| `src/renderer/src/DesktopPage.tsx`        | 真实窗口选择、任务输入、整组执行与结果状态                        |

运行时源码通过已校验指纹的现有 SSH 会话启动为任务级进程；不修改板端模型、系统服务、USB 配置和长期记忆。它复用板端 `agent/hid.py` 与 `.runtime/hid.lock`，与旧桌面 Agent、凭据输入互斥。输入执行不经过 OpenCode。

Windows 观察继续复用 `D:\RK\rk-opencode\pc\observer.py`；该模块新增默认兼容的 `persist_images` 参数。新入口关闭图片落盘，并通过 `measured_call` 获取观察，不写完整观察日志。API Key、实体映射和既有隐私策略继续由原通道管理。

RK 本地规划使用固定策略与 `privacyAgent`。RK + 云端模式接入现有 `CooperativeAgent`，输出也必须通过同一动作组校验；本轮实机验收使用 RK 本地模式，没有将它记作真实云端账户验收。

## 验收结果

正式批量执行记录：[report.json](../.qa/desktop-1793347829511/report.json)，内含源码摘要和测试范围。真实随机测试码不写进任务提示，模型从窗口读取，测试台独立核对输出。

| 指标                     | 本次样例                               |
| ------------------------ | -------------------------------------- |
| 规划请求                 | 1 次，本地模型                         |
| 完整观察/OCR             | 2 次，初始和最终各一次                 |
| 组内快速 UIA 检查        | 4 次，无 OCR 和模型调用                |
| 动作                     | 1 组，字段填充和确认点击各一次         |
| 输入内容                 | 与本次随机 8 位数字完全一致            |
| 提交次数                 | 1 次                                   |
| 发给规划器的观察 JSON    | 734 UTF-8 字节，不含固定策略和任务文字 |
| RK 任务循环耗时          | 23.410 秒，包含一次本地规划            |
| 含启动准备的应用任务耗时 | 约 28.7 秒                             |

同轮还通过：无授权拒绝、顶部提示显示、其他任务互斥、规划期间点击顶部 Stop 后收到 RK 取消确认、取消后无新增业务输入、没有目标窗口时零输入拒绝、无截图或原始观察日志落盘。真实 Electron 两种窗口尺寸与状态截图保存在同一目录。

最终实际发行物再次通过同样的 9 项功能检查和指南文字检查，记录为 [打包程序报告](../.qa/desktop-1793348800672/report.json)。仍为 1 次规划、2 次完整观察、2 个同页动作，闭环 24.300 秒，含准备约 29.3 秒。499 项应用测试、15 项桌面 Python 测试、16 项原有控制提示 Electron 检查通过；测试发现规则已限定到项目 `tests/`，避免并行新增的第三方研究缓存被误当成本项目测试。

这是小样本功能验收，不代表稳定成功率或延迟 SLA。此前单步方案失败保留在 `.qa/desktop-1793346059181/` 和 `.qa/desktop-1793346668015/`：分别出现未验证结果提前结束，以及重复追加数字导致独立核对失败；没有覆盖成通过。旧单步成功样例在 `.qa/desktop-1793346355552/`，不与本轮组成严格速度 A/B。

CPU 验证覆盖整组预检、旧观察、最后一个动作无效时零输入、组内停止、跳页/控件变化、焦点变化、批次动作重放、原有完成文字拒绝和无中间 OCR。运行：
