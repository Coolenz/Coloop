# RK 与云端：有限算力下的数据和记忆边界

日期：2026-11-05。本文区分已实现路径和后续设计；本轮不安装新框架，不迁移记忆库，不部署板端服务。

## 决策

RK 持有用户记忆与执行控制权；普通程序实施授权、字段投影和结果校验；本地模型只处理确实需要语义理解的部分。云端提供获准范围内的推理。不能因为本地模型慢就扩大外发范围，也不能把所有权限判断都实现成一次模型请求。

## 先区分实际入口

| 入口                                              | 实际路线                                            | 本轮影响                                            |
| ------------------------------------------------- | --------------------------------------------------- | --------------------------------------------------- |
| 桌面应用 TaskService（index 注入 executeDesktop） | planTask → TarsAgentService → Harness/TARS          | 收紧云端规划器的记忆工具权限，强化 CloudFields      |
| 桌面 hybrid/auto                                  | 默认 RK 规划；coloop_consult 发送固定问题和批准字段 | 不新增隐私推理调用；本地记忆仍可访问                |
| 桌面显式 cloud                                    | 云端接收目标及获准工具结果                          | 禁止直接读取/修改 RK 长期记忆；这不是全面匿名化模式 |
| 未注入 executeDesktop 的协作问答                  | CooperativeAgent                                    | 单片段省去选择器；问答直接呈现经检查的云结果        |
| DesktopService 结构化协作规划                     | CooperativeAgent 默认 local 回答模式                | 保留最终本地结构化生成，避免动作 JSON 契约损坏      |

旧文档的多轮 RK 隐私 Agent 不是当前桌面主入口。不能把协作问答减少的调用次数当成桌面主路径的性能收益。

## 三条数据通道

### 1. 已批准的结构化字段：零隐私模型调用

用户批准字段定义 → 主机从实际文本/CSV 提取 → 类型和来源检查 → 凭据/PII 规则检查 → 固定问题与字段值交云端。

CloudFields 解析并冻结本任务的授权定义，调用方修改原数组不能扩大范围。字段数量、类型、重复名称和凭据名称在构造时校验。字段投影只在该实例内缓存，每次新来源采集或 clear 都使缓存失效；返回副本防止调用方改写缓存。

该缓存仅复用计算结果，不是网络授权、不存云端结论，也不跨任务共享。原有按字段积累证据的语义保持不变：新来源不包含某字段，不会自动抹去先前来源中的该字段；字段出现歧义或解析失败则清除对应值。下一阶段如需要约束特定文档、记录或来源时效，应增加显式来源标识，不能把当前字段采集当作完整的数据来源权限系统。

### 2. 未分类自由文本：保留语义隐私检查

规则移除凭据/替换已知隐私 → RK 识别未知敏感片段 → 程序替换 → 必要片段选择 → RK 隐私及条件完整性复核 → 冻结投影并做规则检查 → 云端。

只有一个完整来源片段时，程序直接选择它；多个片段仍由原选择器筛选，不自动全选。空来源、超预算、未通过复核都拒绝，不截断后放行。

普通问答的 `answerMode: direct` 在云端结构校验、凭据检查、本次已外发实体引用检查之后，格式化 summary、steps、uncertainties 并在本地精确回填。没有额外 RK 重写，也没有第二模型事实复核。云端答案仅为文本，不能直接执行。

`answerMode` 默认 local，以保留桌面动作 JSON 和需本地信息重建的调用方。该模式仍有原来的最终生成和格式重试约束。

| 单片段协作问答      | 原 RK 调用数          | 本轮 RK 调用数              |
| ------------------- | --------------------- | --------------------------- |
| hybrid 最终路由云端 | 5                     | 3：路由、敏感识别、出口复核 |
| 明确 cloud          | 5（旧问答仍重复路由） | 2：敏感识别、出口复核       |

以上为无重试成功路径的协议调用数，不是实机耗时测量。多片段额外保留一次选择器调用。

### 3. 长期记忆：默认不外发

TarsAgentService 仅为本地模型注册 `coloop_memory_search`、`coloop_memory_catalog`、`coloop_memory_get`、`coloop_remember_preference`。执行前和异步返回后都检查工具所属路线及当前路线；仅在 UI 隐藏工具或提示词中禁止读取不够。

云端失败后切回本地时重新建立本地工具集，恢复本地记忆访问。旧工具引用不能跨路线读取记忆。显式选择 cloud 不被解释为用户同意上传整个记忆库。

经过主机核验的任务证据仍可由主机加入本地后台记忆队列；这与云端模型主动读取或写入记忆工具是两个权限。原有偏好写入必须引用用户明确指令的要求继续保留。

## 第二轮：检索、审计和恢复

### 合并一次记忆检索

`coloop_memory_search` 在一次工具调用中执行 catalog → 校验实际 ID → get，减少原先目录检索后等待模型挑 ID 的一轮生成。查询必须有非空 query 或 tags，默认 3 条、最多 5 条；它不是默认把全库内容塞进上下文。需要逐条挑选时继续使用 catalog/get。

正文不缓存，get 会重新读取记录；目录与正文之间发生删除/过期时保留 missing 信息，维护繁忙时保留 deferred。未知或重复 ID、数量超限、未交代的记录缺失会拒绝。停止或路由变化后不返回在途结果。该工具只读，可按既有恢复规则重新请求，但不会重放旧观察或复用旧完成凭据。省去的是一次工具之间的模型生成，不是板端总耗时测量。

### 诊断日志只存元数据

新的 `tars-events/events.jsonl` 记录使用固定白名单：事件类别、已注册工具名称、完成原因、已知错误码、受限计数及宿主时间。正文、工具参数/返回、任意错误消息、路径和任意标识不写入；当前运行内存里的事件不变。它不参与恢复，因此无需为了诊断再复制一份私人记忆。

该变更不清理旧日志。Harness 的 `host-events.jsonl`、SDK sessions 和执行检查点仍是独立的原文恢复记录，本轮没有把它们伪装成已脱敏日志；后续应通过受支持的持久化加密能力处理，不能删掉去重与未知结果核查所需证据。

### 恢复不能把本地历史带回云端

Harness owner marker 绑定原接收端、模型、协议、headers 的摘要，以及宿主传入的 local/remote 边界。配置在创建运行时即复制；恢复在调和未知动作或启动 SDK 前检查绑定。

同接收端仅轮换 API Key 可以恢复；remote → 不同 remote、local → remote 均拒绝。现有云端失败回退 RK 属于 remote → local，宿主可明确启用此收紧边界的方向：先同步持久化 local 边界，再加载历史。此后即使重新选择原云模型，也不能把已含本地记忆的会话送回云端。边界来自宿主实际路由，不由模型、URL 外观或工具协议推断。

缺少原路由/边界的旧 marker 会拒绝自动恢复并保留原文件；没有自动迁移。该机制不防御有本机文件修改或传输实现修改权限的攻击者。

## 记忆系统的后续方向

沿用已存在的后台 MemoryReviewQueue，不再增加一套记忆框架。前台读取应先限定主体、项目、敏感级别和有效期，再检索；记忆维护在后台合并候选事实和冲突。用户明确偏好使用确定性写入，权限撤销和删除必须立即使读取结果失效。

未来若需让云端使用记忆，需要一个单独的投影服务：传入任务及接收方，输出允许外发的必要字段；保留来源版本、用途和到期范围。不能把 memory.get 的完整工具结果接回云端上下文。本轮尚未新增该投影服务、完整项目隔离、删除墓碑或备份撤销机制。

不建议在 RK 上为每个阶段并发启动多个生成模型请求。共享 NPU 是否支持并发、是否改善总延迟需要测量；本轮通过移除无决策价值的调用缩短串行链路。

## 验证与限制

协议测试覆盖 RK 调用次数、单/多片段、拒绝/取消零出境、实体回填、隐藏实体猜测拒绝、授权对象突变、投影缓存失效、云端记忆工具隔离和云端到本地回退。类型检查和构建验证接口兼容。

第一轮源码验证：`npm test` 共 63 个测试文件通过，1062 项通过、1 项跳过；`npm run build`（包含类型检查）通过。构建仅产生本地 out 产物，没有打包发布或替换运行中的桌面/板端服务。未执行实机 NPU 或公网模型验收。

第二轮当前工作区验证：`npm test` 共 65 个测试文件通过，1111 项通过、1 项跳过；`npm run build` 通过。新增恢复测试使用真实 Harness SDK 和本地 HTTP 模型 fixture，验证同路由续接、密钥轮换、remote → local 收紧后禁止外发、错误/旧 marker 拒绝及零上游访问；不是 RK NPU 或公网模型实测。记忆检索、诊断日志和恢复专项合计 161 项通过。

这些检查不能证明自由文本语义识别零漏报、云答案正确，或桌面显式 cloud 的所有数据已经匿名化。电脑观察助手、云端工具结果、日志和本地历史仍有各自边界。实机 NPU 延迟、真实任务成功率和安装包部署需独立验收。
