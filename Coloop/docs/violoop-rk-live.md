## 联调中修复的问题

1. **HID 适配失配。** 板端原生接口已要求点击包含真实 target_id、键盘操作不带 pointer 字段，并为发送增加可选逐报告 guard。旧 Coloop 适配器仍使用旧字段和方法签名。现转为完整原生请求，叠加任务取消检查并复用原生发送、部分写入检测和按键/按钮释放逻辑，不自行实现另一套原始设备写入。
2. **长窗口标题复制错误。** RK 曾缩写随机标题，正确停止在需要补充。现由本机将用户明确提供的完整标题绑定到真实窗口，给模型窗口编号选择；输入仍要求精确、唯一窗口，不做近似匹配。
3. **本地动作计划误经文字回答流程。** 自动路线选中 local 后仍经过通用分析/实体展示通道，动作 JSON 未通过校验。现使用独立 `desktop-planner.ts`，local 直接以固定桌面策略生成动作 JSON，所有路线仍需完整 schema 校验。cloud 选择复用原隐私检查，避免再次判断路由；本次没有将云端桌面计划记为已通过。

回归新增接口守卫、取消后原生释放、指针编号与键盘字段、窗口编号绑定、raw 动作计划与非法路由拒绝等检查。应用 535 项 Vitest、19 项 Python 桌面执行器测试通过。

同一最终打包程序另通过原桌面 9 项真实检查，固定报告为 `.qa/desktop-1793381612143/report.json`，包含真实本地模型读取另一组随机数字、实际 USB 输入/单次确认、规划期间顶部停止、错误窗口零输入拒绝和观察不落原始图像日志。测试在系统停止后显式恢复，再建立新的缺失窗口任务，没有放宽停止锁。
