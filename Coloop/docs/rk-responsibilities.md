# RK 设备在电脑操作 AI 中的职责

日期：2026-10-30。本文细化 [Coloop 开发方向](development-direction.md) 中的板端职责；部分能力已在单窗口 M1 接入开发源码，具体完成范围以 [电脑操作验收](desktop-operation.md) 为准。

RK 应掌握一个桌面任务从开始到结束的完整执行过程：维护目标和授权范围，取得可信连接上的新观察，选择规划方式，核对候选动作，通过 HID 执行，再检查是否得到预期结果。云端提供规划能力，RK 决定候选动作在当前任务中是否可以执行以及执行后如何继续。

这里的“本地控制”主要由普通程序实现。窗口编号、动作有效期、输入串行、停止和去重无需让 4B 模型反复判断；需要理解文本或任务含义时，才调用本地或云端模型。

## 八项职责

| 职责               | RK 具体负责                                                                  | 是否需要本地模型                                     |
| ------------------ | ---------------------------------------------------------------------------- | ---------------------------------------------------- |
| 任务管理           | 保存目标、允许应用、数据范围、当前步骤、状态和任务代次；处理暂停、接管与结束 | 不需要                                               |
| 观察管理           | 请求最新窗口状态，关联观察编号与目标，维护本轮上下文，拒绝旧观察与迟到结果   | 不需要；语义摘要可按需使用                           |
| 本地数据与出口策略 | 持有本任务数据引用，控制规划请求范围，与电脑端协作完成脱敏和出口检查         | 规则处理为基础，现有语义检查按原策略保留             |
| 规划调度           | 按用户选择与已验收能力，调度确定性技能、本地模型或云端模型，控制调用次数     | 本地规划时需要，调度本身不需要                       |
| 动作校验           | 检查动作格式、目标身份、授权、观察有效期、单次消费和停止状态                 | 不需要；语义建议不能替代这些检查                     |
| HID 执行           | 独占键鼠通道，按校验结果发送报告，控制顺序和释放按键，记录输入是否已发出     | 不需要                                               |
| 结果验证           | 重新观察，核对实际输入、页面状态或保存结果，决定继续、重读、重规划或待确认   | 明确结果用程序核对；复杂结果可按数据策略请求语义判断 |
| 运行保障           | 处理断连、超时、停止、重启和资源占用，记录动作与结果，给界面准确回执         | 不需要                                               |

## 任务管理

一个桌面任务包含用户目标、允许的窗口/应用、允许处理的数据、执行模式、当前步骤、步数和时间预算。任务状态由 RK 维护，Coloop 显示其状态并发送控制指令。首版一个设备只允许一个桌面任务占有键鼠输入权。

任务授权覆盖明确范围内的普通动作，无需每点击一次重新询问用户。动作超出应用、数据或操作范围时，运行时进入待授权状态；模型不能通过新的回答扩大原授权。

每次停止、接管或重新开始都更新任务代次。之后返回的旧规划、旧动作或旧回执不能恢复执行。暂停后继续、设备重连或程序重启时，都先重新观察，不能重放上次未确定完成的动作。

## 观察管理

第一版的截图、OCR、UIA、窗口句柄、前台与焦点事实仍由 Windows 观察助手取得。RK 负责发起观察、核对来源会话与编号、维护本轮状态，并把模型所需的信息整理成有限上下文。

观察应携带任务/会话关联、观察编号、采集时间、窗口身份、显示器与坐标空间、当前焦点和候选目标。模型选择目标编号，电脑端校验器把它解析为实时位置；执行器不把 Coloop 的图片像素直接当桌面坐标。

可以减少发送给规划器的重复文字、保留上一步结果和必要差异，但缓存只用于理解上下文。实际操作仍需最新有效观察；旧观察的动作许可不能因为文字看起来相同而继续使用。云端返回期间如果目标已变化，重新观察或规划。

这是一项双端协作职责：RK 控制是否进入执行，电脑助手提供发送前的实时前台、焦点、遮挡和目标校验。第一版依赖该助手提供的事实，不具备独立视频核验，也不能宣称消除了校验与输入之间的焦点竞态。

## 本地数据与出口策略

RK 维护本任务的本地数据引用，规划器只获得完成下一步所需且允许发送的上下文。例如“把当前文字填到目标输入框”可以使用本地文本引用，云端无需看到完整原文。

本地引用必须绑定来源、用途、目标与任务：模型提出输入某个引用时，执行前核对是否允许把该内容放入当前目标。引用不是任意读取电脑内存或文件的通用权限。

现有实体映射、凭据移除和云端 Key 存储目前位于电脑端，首版继续复用；RK 保存必要引用和检查状态，不为职责划分而复制整套凭据。每次上云仍由电脑端出口网关执行既有检查，RK 参与原有语义检查与任务范围约束，不能直接绕过网关。

既有凭据移除且不回填、原始截图/文件/历史不默认上云的政策保持不变。可以优化重复检查，但需证明字段与内容范围仍然有效；新内容或检查失败不能按旧结论放行。本地模型的敏感识别属于辅助能力，不能承诺覆盖所有语义隐私。

## 规划调度

2026-10-31 明确的最终目标是：手机向 Violoop 发任务，RK 接收并为每一轮选择本地技能、本地模型或云端规划；手机用户无需逐条选择模型。RK 依据已验证能力、当前观察和任务结果判断是否需要云端，调用范围仍受本任务的数据策略约束。具体链路见 [手机任务主线](development-direction.md#手机任务主线2026-10-31)。

开发源码现已为手机任务增加 `auto` 规划模式和桌面专用 RK 路由策略；local 使用独立桌面动作策略，cloud 复用既有隐私协作，桌面手动模式继续保留。单窗口自动本地路线已通过 [真实 RK 联调](violoop-rk-live.md)，云端桌面路线、广泛同题测量和能力校准仍待验收。不能仅根据模型自报“我有把握”判断是否适合本地完成，也不能在离线失败后自动扩大上传范围。

可用的执行方式分为三类：

- 确定性技能：对已知目标输入已授权文本、等待已知状态、检查已知结果等，由程序完成。
- 本地模型：在已验证范围内解释短文本、提出简单下一步或匹配已注册技能。
- 云端模型：处理复杂跨应用规划、未覆盖场景和需要重新理解目标的失败。

按用户最新优先级，同一页面能完成的业务动作由规划器一次提出动作组，RK 预检整组、连续执行，组后统一观察和验证；不按读数、输入、确认分别推理。组内只做快速的窗口、目标和焦点校验，不进行 OCR 或逐动作业务进度记录。遇到跳页、目标变化或需要未知结果才能决定的步骤，结束当前组后再规划。

本地语义摘要、隐私分析、动作规划共用 NPU 时，需要统一调度，避免一项业务动作触发多轮冗余推理。优化不能省掉仍有必要的数据检查；停止与键鼠释放也不能等待模型推理结束。

## 动作校验

收到候选动作后，先校验动作类型和字段，再检查任务是否仍在执行、是否获准操作该窗口与数据、观察是否有效、目标是否唯一、动作是否已经消费。

执行前请求电脑助手进行实时校验：窗口仍是目标窗口，输入焦点仍符合预期，控件可用且未被遮挡。跨窗口切换以后必须重新观察，不能继续沿用上个窗口的目标编号。

校验通过后，本地执行层生成绑定任务、动作和观察的一次执行凭据，串行提交给 HID。模型不能生成用户授权、解除停止状态或指定任意设备节点。现有文件快照的签名许可与桌面输入的授权对象不同，不能直接通用。

这一层验证的是动作范围和执行条件；动作在语义上是否能完成用户目标，还需要规划与结果检查共同判断。

## HID 执行

RK 复用现有 USB 键盘和绝对坐标鼠标通道，按已验证目标位置执行点击，按明确参数发送快捷键或文本。执行期间只有一个输入所有者，避免两个任务交错按键。

执行器要区分尚未发送、已经发送和结果未知。I/O 超时或断连后可能已经产生部分输入，此时记录实际阶段并重新观察，不直接重发整个动作。停止时阻止新的业务输入，尝试释放按键和按钮，并向任务管理器回执。

当前 HID 文本实现限 1～64 个 US 布局 ASCII 字符。中文先由已授权电脑助手提供 Unicode 文本通道，再通过 HID 粘贴；更长文本、输入法、滚动和拖拽均需相应扩展和验收。不能把当前报告编码能力外推为任意应用的输入兼容性。

## 结果验证

动作完成后主动重新观察，再决定下一步。输入后检查目标字段的实际值，点击后检查预期状态；保存任务还要由获准的电脑助手核对新文件或应用保存状态。窗口关闭、工具成功和模型说“完成”都不能单独作为保存成功的依据。

已注册技能可以使用明确的结果条件直接核对。通用任务无法用规则确定时，在现有数据策略内请求模型判断，或标为待确认；不能把“无法验证”当作成功。

效果尚未出现时，先有限等待并重读观察；确认前提改变时，再重新规划。重试输入与点击要判断先前动作是否已生效。运行时还要限制总步数、无进展轮次与重复动作，避免在错误页面持续操作。

## 运行保障

停止处理采用独立于模型调用的路径。收到用户停止、观察助手断连或心跳过期后，RK 撤销本任务未发送的业务动作，丢弃迟到规划结果，尝试释放按键，并报告是否已完成撤销。Coloop 在收到板端确认前显示正在停止；已发出的动作仍需核查结果。

设备或服务重启后保持未授权执行状态。任务可保留进度供回看，但恢复必须重新确认会话与观察。首版不把重连、睡眠或锁屏后的恢复解释为继续执行的许可。

资源管理以桌面前台任务优先：HID 和停止处理不依赖 NPU；本地推理遵守现有锁与忙碌反馈；记忆整理在空闲时进行，不挤占当前动作的规划。只管理本任务持有的资源，不终止其他会话的共享推理进程。

审计默认记录任务/观察/动作关联、规划来源、校验结果、执行阶段、结果状态与耗时。完整屏幕文字、截图、文本引用对应的正文和密钥不默认写入该审计。日志策略需要独立实现与验收，不会自动改变现有聊天历史或旧日志的存储行为。

## 一个任务中的具体配合

以“把浏览器当前选定文字保存到已打开的文本编辑器”为例，完成目标包括内容正确和新文件保存成功：

1. Coloop 收集允许操作的两个窗口和新的测试保存位置，向 RK 建立任务。
2. RK 请求浏览器观察；电脑助手取得当前文本及本地引用。原文可以留在电脑，RK 只持有受任务约束的引用。
3. RK 经出口网关把允许发送的目标、控件信息和文本引用描述交给云端，请求下一步；必要的新文字仍按原隐私策略检查。
4. 云端建议切换到目标编辑器。RK 检查切换范围，调度获准的切换动作，再取得编辑器新观察。
5. 云端或已注册技能提出在目标输入区使用该文本引用。RK 核对来源、用途、目标和焦点，由电脑助手准备文本，RK 通过 HID 发送粘贴快捷键。
6. RK 请求回读，核对编辑器内容，再执行保存步骤；电脑助手核对获准的新文件，RK 据此结束任务。

这个例子属于跨应用与中文输入阶段的目标流程，尚未交付。它体现的是：云端决定业务下一步，RK 掌握每一步的执行条件与进度，电脑助手提供当前系统事实和获准的数据访问。

## 首版边界与开发优先级

| 优先级 | 先落地的部分                                          | 验收重点                                                                                    |
| ------ | ----------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| P0     | 任务状态、现有观察/HID 接入、动作校验、停止、结果回读 | Coloop 内完成隔离窗口随机输入闭环；旧观察、已消费动作及停止后的迟到结果不能继续发送业务输入 |
| P1     | 允许窗口切换、中文文本引用、保存验证、同一规划接口    | 两个真实应用间转移本次文本，保存到新的测试文件，内容独立核对                                |
| P2     | 经过验证的技能、本地/云端路由、观察增量与资源优化     | 同题比较成功率、耗时、模型调用次数，保留失败并确认没有扩大数据出口                          |

此处的职责划分不要求先把 Windows OCR、所有隐私映射和云端密钥迁到板上。先让 RK 接管任务循环与输入权，再根据独立硬件目标迁移感知与网关。独立物理确认仍是后续硬件能力，同一 RK 系统内的软件校验不能替代独立 MCU 隔离。

现有可复用基础为 `D:\RK\rk-opencode\agent\desktop.py`、`agent\hid.py`、`pc\observations.py`；[现有验证范围](../../RK/rk-opencode/VALIDATION.md)与新模块的完成情况应分别记录。
