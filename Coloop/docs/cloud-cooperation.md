# RK 与云端的隐私协作

2026-11-05 更新：当前桌面主入口与本文的 CooperativeAgent 问答链路不同，见 [有限算力下的数据和记忆边界](rk-cloud-boundary.md)。协作问答现已启用直接呈现；桌面结构化规划保留本地最终生成。下文的最终 RK 生成规则仅适用于 `answerMode: local`（默认）。

2026-10-30 新增的软件链路，使用现有 Qwen3.5-4B 服务和已配置的云模型。此处定义本项目自己的敏感边界；参考 Violoop 的本地优先、必要摘要上云思路，没有宣称与其软件或硬件等价。

## 数据路径

```text
本次问题 + 附加文本 / 本机 OCR
  → 本机凭据移除、已知身份字段随机占位
  → RK 路由 Agent：local / cloud / blocked
      local → RK 回答
      cloud → RK 敏感片段识别 → 主机确定性替换 → RK 选源片段 ID
            → 主机逐字摘录必要事实 → RK 隐私与条件完整性复核
            → 主机冻结并检查摘要 → 云端分析 Agent → 严格 JSON 校验
            → 问答：程序格式化并回填本次已外发的非凭据占位符
            → 结构化规划：RK 结合本地实体映射核查和回答 → 本机回填
```

工作台默认「RK + 云端协作」。保留「RK 端侧模型」作为只在板端处理的原有入口。旧 IPC 的 `target: cloud` 也经过协作流程，不能绕过隐私检查直接发送原文。「测试连接」仅使用固定测试短句，不携带任务或历史。

当前任务系统没有多轮会话 ID 或消息列表，因此首版范围是本次 `prompt + context`，屏幕任务还包括本次 OCR 文本。不会自动拼入运行历史、Mem0、其他 Agent 会话、截图像素或文件。需要完整多轮上下文时，调用方必须先明确会话结构与边界，不能将全部历史当作同一会话上传。

## 敏感信息政策

| 内容                                                             | 本项目处理                                                                       |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 密码、API Key、Token、Cookie、私钥、认证头等凭据                 | 移除为 `[REMOVED_SECRET]`，不交云端，不允许最终答案回填                          |
| 身份、联系方式、证件、地址及内部路径／网络地址                   | 使用任务内随机占位符；映射仅在上位机内存，本地回答可使用必要原值                 |
| 客户／公司／项目真实标识、业务数值、未公开代码及其他业务私密内容 | RK 提取私密片段并生成抽象问题；主机验证片段来自本次输入后替换，RK 再独立复核摘要 |
| 原始图像、完整资料、历史、长期记忆、映射表                       | 不进入云端调用参数                                                               |
| 公共技术概念、匿名关系和必要约束                                 | 仅保留解决当前问题必需的摘要                                                     |

可在文本中显式使用 `<private>…</private>` 标注可在本地恢复的私密片段，使用 `<secret>…</secret>` 标注永不回填的秘密。标签必须配对，不支持嵌套；未知、残缺标签或伪造系统占位符会拒绝整个协作任务。标记是补充手段，不能代替自动检测或业务语义判断。

`PrivacyVault` 检测常见凭据、邮箱、手机号、身份证、IPv4、URL 和文件路径，跟踪已知私密值及部分编码形式，拒绝其他任务的占位符。语义片段由 RK 判断；规则不可能覆盖所有敏感形式，同一模型的两次判断也不是语义无泄露证明。业务语义、拆分／改写／编码变体仍需要扩大真实题集验证。对高敏任务可使用 RK-only；当前软件不能作为通用 DLP 或物理隔离保证。

## 两端 Agent 的约束

RK 路由、敏感片段识别、资料选择、出口复核和最终回答分别使用主进程固定的 system 策略；任务内容放在 JSON 数据字段，不能改写策略。路由与出口复核只接受固定字段 JSON，敏感识别只接受最多 32 项的严格字符串数组，片段必须实际来自本次输入；`null`、不合法 JSON、重复键、额外字段、未知枚举均拒绝。不修补或抽取 Markdown 中的 JSON，不把失败输出当作许可。

资料阶段使用摘录式摘要：主机把已掩码的本次问题与参考文本按完整句子／换行分成最多48个片段，保留句内逗号、数值和原有条件，RK 仅选择1～6个本 registry 的短ID。主机按原始顺序逐字组装 `facts`，`question` 是固定的通用分析指示；不能由模型改写、补造或截断事实。片段ID只是当前来源集合的选择器，不授予文件读取或执行权限。投影整体最多3000 UTF-8字节，过长、未知／重复ID或没有足够安全片段就拒绝。RK 复核同时检查敏感信息和判断所需条件是否遗漏；仍不能证明模型必定选对全部片段。此修正源于真实DeepSeek测试发现旧自由摘要丢失A/B具体条件，而非继续用固定云回复掩盖问题。

输入超过 RK 的保守上下文预算就拒绝，不默默截掉策略或上下文。

2026-11-05 起，只有一个完整来源片段时由程序直接选择，省去资料选择 Agent；多个片段仍执行上述选择流程。单片段仍需敏感识别、3000 字节预算检查、RK 出口复核和确定性出口检查。协作问答显式选择 cloud 时复用该可信路由，不重复调用复杂度路由 Agent。

所有协作 RK 调用发送 `X-RK-Privacy: metadata-only`、关闭请求缓存、禁工具，必须已声明隐私能力且返回确认头。输出截断、非 `stop`、工具调用均拒绝。使用现有前台活动登记等待记忆维护让路，结束释放自有登记，不召回／写入 Mem0，不修改模型库、Runtime 或权限审批链路。

云端只接收 `{question, facts}`，没有本地映射或原始请求参数。固定 Agent 策略要求短 JSON：

```json
{ "summary": "简要结论", "steps": ["建议步骤"], "uncertainties": ["未确认事项"] }
```

OpenAI 兼容、Anthropic、Gemini 均禁工具，通用输出上限512 tokens。官方 `https://api.deepseek.com` 的 `deepseek-flash`／`deepseek-v4-pro` 分析请求单独启用低强度思考，预算2048 tokens（包含内部推理），并请求 `response_format: json_object`；其他端点／模型不附这些专属字段。返回提示要求250字以内的最终JSON，主机硬性检查完成原因、结构、重复键、字段、长度及占位符，分析文本最多4096 UTF-8字节，HTTP响应体最多32768字节。内部推理不作为分析结果发布，不能把512 token截断当作成功，也不关闭思考后以合法JSON冒充正确计算。

云端结果始终先通过结构、凭据和本次已外发实体引用检查。`answerMode: direct` 用于协作问答，由程序格式化结果并精确回填，不再运行 RK 最终语义核查；默认 `local` 模式仍交 RK 生成最终回答，以兼容桌面动作 JSON。两种模式都不能由云端结果授权读取、Shell、HID、联网或审批操作。OpenAI 请求附 `store: false`；该字段不等于第三方服务商无日志承诺，保留政策仍取决于选定端点。DeepSeek参数依据其[Chat Completions接口](https://api-docs.deepseek.com/api/create-chat-completion/)与[JSON Output说明](https://api-docs.deepseek.com/guides/json_mode/)，语法JSON仍需本机字段验证和内容验收。

云端只允许引用本次实际摘要中出现的随机实体 token，不能猜测同一任务中未出境的实体。最终 RK 阶段使用单独的短实体 ID 与仅本地可见的映射，减少小模型抄写长随机串的错误；这些 ID 不能出现在云摘要或云返回中。有实体时，RK 只返回 `{"entity_ids":["E1"],"answer":"分析正文"}`，主机严格验证所选 ID 已存在且不重复，再按原始映射显示「实体名称：分析正文」。正文可以使用授权的本地身份／业务原值，但不能含未解析占位符、凭据移除标记或已知凭据；未知／残缺 ID、额外字段、重复键拒绝。没有实体的任务采用独立的普通文本回答策略。

身份／业务原值允许在授权的最终本地结果中呈现，凭据始终不能恢复。呈现字段来自 RK 明确选择的合法 ID 和本地原始映射，并非修补模型抄写的原值；RK 原始输出与最终显示分开验收。不做模糊匹配、纠错或补全。模型仍可能选错已有实体或改变分析语义，因此仍须验收最终任务正确性，不能仅由替换算法声称任务必定成功。

复杂度判断只允许进入脱敏阶段。取消、截断、隐私检测命中或服务故障都会结束任务，没有原文上云兜底。仅最终本地实体回答的 JSON 语法／结构错误允许一次真实重新生成：使用同一份本地输入和固定格式纠正策略，不修改、强转或补全第一次输出，不再次请求云端；第二次仍错误就失败。结构解析成功后发现的未知／重复 ID、正文凭据及未解析标记直接拒绝；重复 JSON 键也直接拒绝。首次结构不合法时不采纳任何字段，只允许上述一次本地重生，不能声称已检查到这些字段的语义。首次拒绝与第二次实际模型结果分别记录。停止等待不代表终止共享 NPU；迟到回答不发布，也不继续下一阶段。

## 本地记录与验证口径

映射、中间摘要和云端分析只存在本次主进程调用内存，结束清除引用；JavaScript 清引用不等于物理内存擦除。任务历史沿用原有本地明文记录，保存用户问题和最终回答；凭据移除不追溯清理已有问题、旧日志、OpenCode 数据库或备份。不要把云端脱敏表述为本地历史已加密或整体脱敏。

协议与策略测试：`npm test`、`npm run typecheck`、`npm run test:e2e`。`tests/cooperative-npu.mjs` 使用真实 RK 与回环云协议 fixture，原始结果位于独立 `D:\RK\logs\coloop-cooperative-*` 目录；fixture 不消耗真实云账户，不能证明付费端点或任意真实业务的成功率。实际运行结果另见 RK 专题与验收记录，源码存在不等于安装版已经更新。
