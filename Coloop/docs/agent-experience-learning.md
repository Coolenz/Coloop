# Agent 执行经验学习与 Qwen 适配

记录日期为 2026-11-08，Asia/Shanghai。用户要求记录经验学习架构及 GitHub 项目，并评估当前 Qwen 的适用性。本记录用于后续设计，ACE 接入和模型收益尚待实现与实测。

## 架构研究方向

建议以 ACE 的经验提炼和增量更新为主框架，结合 Agent Workflow Memory 的可复用工作流表示，通过 DSH 原生会话、工具注册和生命周期扩展接入现有执行链路。

执行闭环为用户任务 → 相关经验召回 → DSH 执行 → 工具结果与业务核验 → 保存案例 → 提炼候选经验 → 增量合并 → 后续任务使用及效果记录。

经验数据分为执行案例、可复用工作流、策略与失败经验。条目包含适用条件、动作建议、核验方式、来源任务、环境版本、支持案例、反例及最后验证时间。任务结果分别记录核验成功、核验失败、结果待确认和取消。归因推测保留候选状态，后续证据用于修订。

## 当前 Qwen 的适用性

源码配置对应 RK3588 上的 Qwen3.5-4B，模型标识为 `qwen35-4b-rkllm`。容量代码支持服务健康信息、已验证配置及兼容配置三种来源。兼容配置为 16384 token 上下文、1024 token 输出，运行时容量以实际服务声明及输入传输限制为准。本次依据源码配置判断，板端实时状态尚未读取。[模型服务](../resources/rk-model-service.py)、[容量定义](../src/shared/local-model.ts)

工程判断是适合先实现小规模、结构化的经验使用和单案例提炼。复杂失败归因、跨任务抽象、矛盾经验整理需要单独验证。当前查阅的 ACE 论文和官方仓库未提供这套 RK/Qwen 部署的效果证据。

| 职责 | 建议实现 |
| --- | --- |
| 执行与经验使用 | Qwen 读取少量匹配当前任务的短条目，结合当前观察执行 |
| 单案例提炼 | 向 Qwen 提供精简的目标、关键回执、核验结果，输出少量候选经验 |
| 复杂反思 | 先验证本地模型表现，困难案例保留来源供后续处理 |
| 经验合并 | 程序校验结构、来源、条目 ID 和版本，模型提出语义合并建议 |
| 结果评价 | 使用工具回执与业务核验，另记录经验是否被采用 |

初始试验可每次召回 1–3 条经验、每个案例提炼 1–2 条候选，先做单轮提炼。这些数量是可调整的实验起点。输入统一核对实际字节和 token 容量，输出检查完整性与结构。任务结束后的整理复用现有队列和模型互斥，费用及本地私密数据边界沿用项目约定。

## 验证设计

使用隔离 profile 和 QA 记忆命名空间。固定模型、任务起始状态和执行预算，对比无经验、人工核验经验、Qwen 自动提炼经验三组。经验只来自此前训练任务，测试加入参数变化、相似新任务、环境变化和失败恢复，避免测试结果进入先前经验。

记录任务成功率、错误复发率、恢复成功率、步数、耗时、模型用量、结构化输出有效率和错误经验比例。先用小任务集筛查可行性，再扩大样本验证收益。

本轮仅新增研究记录，完成来源和源码局部核对。模型实验、应用测试、构建、目录包验证和安装验收均未执行，当前安装版继续使用。本轮未产生构建或验证副本。

## 2026-11-13 经验保存可靠性改进

现有后台任务学习链路增加了逐分片存储回执校验。真实用户选择的待写状态进入持久任务日志，写入失败后自动重试，重启后使用原事件身份和工作区继续保存。召回时遇到格式损坏的选择元数据，会跳过该案例并保留其他有效记忆。CLI 可通过 `status.value.autoAgentWork.tasks` 检查反馈和选择的保存状态，操作示例见 `docs/cli.md`。

本次选择先处理经验保存和召回可靠性。通用失败经验提炼、ACE 增量整理及学习前后成功率评测仍待实现。测试环境中，QA 记忆命名空间的旧记录读取还受最新五条目录校验限制，后续需独立修复并验证读取范围。此前已经标记完成的历史来源回执继续保留，避免重新写入用户后来删除的记忆。

用户随后明确优先执行成功率与自动纠错，并将交付范围限定为源码与测试。本轮进一步补齐已识别本地模型异常直接抛出时的授权云端接续，以及聊天历史读取中断后的只读恢复分类。两项修复复用现有 DSH 会话和恢复机制，通过合成故障回归核对接续、取消和未知副作用边界。
