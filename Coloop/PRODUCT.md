## Platform

web

Electron 桌面应用运行于 Windows，React 前端通过隔离的 preload API 连接本机服务。Android 原生 Kotlin / Jetpack Compose App 以 Coloop 聊天为首页，顶部显示电脑与 RK 连接状态，通过配对加密协议访问同一台电脑。

电脑控制使用屏幕顶部的独立状态小窗，先显示再下发指令。主窗口关闭后驻留托盘；用户可从提示窗或托盘停止控制。

## Product Purpose

2026-11-03 当前路线按用户后续要求切换为云端直接动作：上位机保留OCR与灵动岛交互，RK Qwen仅判断是否值得建议；OCR原文交云端生成建议与明确结构化动作。主动建议点击执行，明确任务直接执行，缺信息在灵动岛回答。RK持有Agent控制循环，对云端动作纯程序校验并经原生USB执行，不再调用Qwen转换；Mem0按tag先查目录再按需取正文。既有手机任务主线和历史构建保留，独立入口`start-proactive.cmd`，详见[主动建议说明](docs/proactive-agent.md)。

2026-10-31 补充确认手机端主线：用户在 Coloop 手机 App 给自己的 Coloop 发任务消息，由 RK 接收目标、判断是否需要云端模型，再组织鼠标/键盘操作电脑，回传进度与结果。例如打开 QQ 邮箱、填写并发送用户指定的邮件。Coloop 是此任务链路中面向用户的聊天名称；旧协议中的 violoop 字段仅用于兼容；具体部署与通信拓扑另行实现，不据此假定手机已经可以直连 RK。

目标链路为“手机消息 → Coloop → RK 本地处理与路由 → 按需云端规划 → RK 校验与 HID 执行 → 观察验证 → 手机回执”。云端为 RK 按需调用的能力，任务状态与输入控制仍由 RK 掌握。开发源码与 Android 0.3.0 已接入独立 RK 任务消息、补充信息、进度与停止；真实 RK/HID 的单窗口自动本地路线已通过公网安卓闭环，云端桌面路线仍待验收。当前执行器限单窗口 ASCII；跨应用及 QQ 邮箱完整流程仍待开发。使用和实际边界见 [Coloop 手机任务](docs/violoop-mobile.md)，后续按 [手机任务主线](docs/development-direction.md#手机任务主线2026-10-31) 推进。

2026-10-30 确认的开发定位：Coloop 是以 RK 设备为执行端的电脑操作 AI。用户提出目标后，由 Coloop 组织屏幕观察、模型规划、动作执行和结果回读，逐步完成电脑上的任务。名称保持 Coloop。

产品主线是“观察 → 规划 → 校验 → 键鼠执行 → 再观察”，云端模型提供复杂规划能力，RK 负责本地任务状态、动作约束和 USB HID 执行；本地模型按实测能力承担简单任务。其他 AI 助手的连接、审批与协调作为扩展能力。分阶段方案见 [开发方向](docs/development-direction.md)。

## Operating Context

新增 Windows OpenCode 会话注册、空闲会话追加消息、受管执行中断与回执。仅观察、OCR 和普通模型推理不显示正在控制电脑。Android 原生客户端通过独立加密网关接入同一会话控制服务，支持临时公网隧道异网连接；其他 AI 会话接入仍待开发。具体边界见 docs/session-control.md 与 docs/android.md。

当前分析模式使用本机 OCR；默认由 RK 判断复杂度、识别私密片段和复核短摘要，仅将必要脱敏摘要交云端，结果再由 RK 结合本地资料回答；API Key 使用 Windows 加密存储。现有协作只包含本次问题和附加文本。桌面窗口最小 1060 × 720。

下一阶段建议先采用“Windows 观察助手 + RK 执行 + 云端规划”的协作方式，沿用现有板卡、模型和 USB 通道。桌面任务需要独立的动作协议与状态机；现有回答 JSON 和文件读取许可不能直接用来驱动键鼠。默认不上传原始截图、文件或历史的现有边界继续适用。
